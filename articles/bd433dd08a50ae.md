## はじめに

自分はWASMに可能性を感じており、WASMを用いた開発をどんどん行っていきたいなと思っています。

ViteでRust製のWASMを使った開発をしていると、Rustのコードを変更するたびに手動で`wasm-pack build`を実行し、ブラウザをリロードする必要がありました。

既存の`vite-plugin-wasm`はWASMモジュールのインポートやHMR自体には対応しているのですが、Rustのソースを変更したときに自動でWASMをビルドしてくれるわけではありません。つまり、`.rs`ファイルを保存→手動で`wasm-pack build`→ブラウザで確認、という流れになります。

これが地味に面倒だったので、Rustファイルの変更を検知して自動でwasm-packビルド→HMRまで一気通貫でやってくれるViteプラグイン **vite-plugin-wasm-hmr** を作りました。

本当はNext.jsでやりたかったのですが、Turbopackはまだプラグインを作成できなさそうなのでViteのプラグインを作成しました。

https://github.com/Coxless/vite-plugin-wasm-hmr

## vite-plugin-wasm-hmrとは

`vite-plugin-wasm-hmr`は、Rustのソースファイルを監視し、変更を検知するとwasm-packで自動ビルドしてViteのHMRをトリガーするプラグインです。`vite-plugin-wasm`の補助で使うイメージです。

主な特徴：

- `.rs`ファイルや`Cargo.toml`の変更を自動検知
- wasm-packビルドを自動実行
- ビルド完了後にViteのHMRをトリガー（フルリロード不要）
- 別プロセスでのウォッチャー起動が不要（Viteプラグインとして完結）
- `vite-plugin-wasm`と組み合わせて使用

## 仕組み

プラグインの内部動作は以下のような流れになっています。

```
*.rs / Cargo.toml を保存
  → fs.watch() で変更を検知
  → デバウンス (300ms)
  → wasm-pack build --target bundler --dev → pkg-staging/
  → pkg-staging/ → pkg/ にコピー
  → Viteのモジュールグラフを無効化
  → server.reloadModule() でHMRトリガー
  → ブラウザに変更が反映される
```

### ポイント

#### Viteのウォッチャーではなくfs.watch()を使用

Rustのクレートは通常Viteのプロジェクトルートの外に配置されるため、Viteの内蔵ウォッチャー（chokidar）では検知できませんでした。

#### ステージングディレクトリによる安全なビルド

wasm-packの出力先を`pkg-staging/`にし、ビルド完了後に`pkg/`へコピーしています。これにより、ビルド中に中途半端なファイルが配信されるのを防いでいます。

#### ビルドキューイング

wasm-packの実行中に新たな変更が発生した場合、キューに入れて現在のビルド完了後に再ビルドを実行します。連続した変更は1回のビルドにまとめられるので、無駄なビルドが走りません。

## インストール

```bash
npm install -D vite-plugin-wasm-hmr
```

前提として以下が必要です：

- **wasm-pack**: `cargo install wasm-pack`
- **vite-plugin-wasm**: `npm install -D vite-plugin-wasm`

## 使い方

### vite.config.ts の設定

```ts
import react from "@vitejs/plugin-react";
import wasm from "vite-plugin-wasm";
import { wasmHmr } from "vite-plugin-wasm-hmr";
import { defineConfig } from "vite";

export default defineConfig({
  plugins: [
    react(),
    wasm(),
    wasmHmr({ crate: "../wasm" }), // Rustクレートへのパス
  ],
});
```

`crate`オプションにRustクレートへのパスを指定するだけで動作します。パッケージ名は`pkg/package.json`から自動検出されます。

### WASMモジュールのインポート

```ts
import { greet } from "my-wasm-pkg";
greet("world");
```

あとは`.rs`ファイルを編集して保存すれば、自動でビルド→HMRが走り、ブラウザに変更が反映されます。

### WASMパッケージの解決

WASMパッケージをアプリから参照できるようにする必要があります。モノレポ構成の場合はワークスペースパッケージとして設定するのがおすすめです。

```yaml
# pnpm-workspace.yaml
packages:
  - apps/my-app
  - apps/wasm/pkg
```

```json
// apps/my-app/package.json
{ "dependencies": { "my-wasm-pkg": "workspace:*" } }
```
