## はじめに

最近サプライチェーンアタックが話題だと思います。ローカルの開発環境で、サプライチェーンアタック等の脆弱性のあるパッケージをインストールしてしまうと、コードだけでなく.env内の機微な情報が流出してしまう可能性があります。そこで、`.env`の情報を平文で保存しないようにするツールを作成しました。

動作としては、「暗号化したまま保存して、コマンド実行時だけメモリ上で復号」するもので、**dotenvx**と類似のものです。ただ、dotenvxは独自の暗号化方式しか使えないため、SOPSやAWS KMSなど既存の暗号化基盤を流用できません。

そこで**どんな暗号化プロバイダにも対応できる**ツールを目指し、**execenv**を作りました。

:::message
まだ、MVPとしてSOPSにしか対応していません。プロバイダは増やしていければと思っています。
:::

## execenvとは

execenvは、暗号化された`.env`ファイルを**メモリ上でのみ復号**し、ターゲットコマンドに環境変数として渡すツールです。

- 暗号化バックエンドを差し替え可能な設計（MVPとして現在はSOPSのみ対応）
- 平文がディスクに一切書き込まれない
- パイプを使わず、`execve`でプロセスごと置換することで秘密が残らない
- Rustで実装

https://github.com/Coxless/execenv

## dotenvxとの違い

dotenvxはDotenv公式が提供する高機能ツールですが、暗号化には独自方式（DOTENV_PRIVATE_KEY）しか使えません。

| 比較項目 | dotenvx | execenv |
|---|---|---|
| 暗号化方式 | 独自のみ | プロバイダで差し替え可能 |
| SOPSサポート | ✗ | ✓ |
| AWS KMS等 | ✗ | 将来対応予定 |
| 平文のディスク書き込み | なし | なし |
| 実行方式 | サブプロセス生成 | execveでプロセス置換 |

既存のSOPSやKMS基盤をそのまま活用したい場合にexecenvが選択肢になるかと思います。

## 仕組み

処理の流れは以下のとおりです。

```
.env.enc（暗号化済み）
    ↓ SOPSで復号（メモリ上のみ）
環境変数として構築
    ↓ execve でプロセス置換
ターゲットコマンド（next dev など）が起動
    ※ execenv プロセスはここで消滅
```

`fork` + `exec` のようにexecenvがバックグラウンドで生き続けるのではなく、`execve`でプロセスそのものを置き換えるため、復号処理を担ったプロセスがターゲット起動後に残りません。

## セキュリティの工夫

秘密情報が窃取されにくくするために、以下の対策を実装しています。

| 機構 | 効果 |
|---|---|
| `execve`でプロセス置換 | 復号を担ったプロセスが消滅し、秘密がメモリから消える |
| `Zeroizing<T>` | 復号文字列がスコープを抜けた瞬間にメモリから削除 |
| `PR_SET_DUMPABLE`（Linux） | コアダンプやメモリダンプを防止 |
| パイプを使わない | プロセス間通信を経由しないため盗聴リスクを下げる |

`execve`の使い方がポイントで、通常のサブプロセス実行（`fork` + `exec`）とは異なり**自分自身をターゲットコマンドに置き換える**ため、復号処理を行ったプロセスはそもそも残りません。

## インストール

**npmでインストール（Linux x64）**

SOPSがPATHに存在する必要があります。また、現在はLinux x64のみ対応しています。

```bash
npm install -D @coxless/execenv
```

**ソースからビルド（Rust 1.93以上が必要）**

```bash
cargo install --path .
```

## 使い方

### 1. ageキーを生成して`.env`を暗号化

```bash
# ageキーを生成
age-keygen -o key.txt

# .envをsopsで暗号化
sops --encrypt --age $(grep "public key" key.txt | awk '{print $NF}') .env > .env.enc
```

### 2. execenvで実行

```bash
execenv --provider sops --file .env.enc -- your-app arg1 arg2
```

Next.jsの場合は↓のように使えます。

```bash
SOPS_AGE_KEY_FILE=./key.txt execenv --provider sops --file .env.enc -- next dev
```

※ ageのキーをデフォルトパス（`~/.config/sops/age/keys.txt`）に保存している場合は、`SOPS_AGE_KEY_FILE` の指定は不要です。

これだけで`.env.enc`がメモリ上で復号され、`next dev`に環境変数として渡されます。平文の`.env`ファイルはディスク上に存在しません。

## 今後の展望

MVPとしてSOPSプロバイダのみ実装しています。将来的には以下に対応したいと考えています：

- AWS Secrets Manager / SSM Parameter Store
- GCP Secret Manager
- HashiCorp Vault

これらに対応したときのメリットを、よくある代替手段と比較すると分かりやすいかと思います。

execenvがこれらのプロバイダに直接対応することで、シークレットマネージャーからメモリ上へ直接取得してそのままターゲットコマンドへ渡す流れが実現できます。

プロセスリストへの露出が防止でき、よりセキュリティが向上するのではと思っています。

また、追加依存がなくなったり、コマンドがシンプルになる効果もあると考えています。

例: HashiCorp Vaultの場合のコマンド例

```bash
env $(vault kv get -format=json secret/myapp | jq -r '.data.data | to_entries | .[] | "\(.key)=\(.value)"') \
pnpm dev
```
