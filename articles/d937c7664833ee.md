## はじめに

Claude Codeに作業を任せている最中に、「ちょっと `git diff` を見たい」「ログを確認したい」「`vim` でファイルを覗きたい」と思うことがよくあります。Claudeに頼むほどでもないので自分で確認したいのですが、そのたびに別のターミナルへ移動して、確認して、また戻ってくるのが地味に面倒でした。

さらに、確認した結果をClaudeに伝えたいときは、コピーしてプロンプトに貼り付ける必要があります。

そこで、Claude Codeを抜けずにその場でターミナルを開けて、選択したテキストだけをClaudeに渡せるModを作ってみました。

https://github.com/Coxless/cc-terminal-mod

## Claude Code Terminal Modとは

Claude Codeの公式Mods機構の上で動く、ターミナルペインのModです。

<!-- ![Terminalペインを開いた様子](/images/d937c7664833ee/terminal-pane.png) -->

主な特徴:

- ペインの中で普通のシェルが動く（`vim`、`less`、`top` も使える）
- ペインを閉じてもシェルは残る（環境変数、cwd、バックグラウンドジョブもそのまま）
- Terminalの内容は自動ではClaudeに渡らない。人が選択して、明示的に渡したものだけが渡る
- Claudeの作業中でも開ける・渡せる
- 公式のMods APIだけで実装（Claude Code本体へのpatchや非公開IPCは使っていない）

3つ目は意識して設計したところです。Terminalで何を実行しても、選択して渡す操作をしない限りClaudeのContextには入りません。

## できること

| やりたいこと | 操作 |
|------|------|
| ターミナルを開く | `/term` |
| ターミナルを閉じる（シェルは残す） | `/term-hide` |
| マウスで選択したテキストをClaudeに渡す | `/term-add` または `[ Add to Claude ]` ボタン |
| キーボードだけで選択して渡す | `alt+v` で選択モード → `enter` |
| 履歴をさかのぼる | ホイール、`shift+PageUp` / `shift+PageDown` |

Claudeに渡る内容は以下のような形です。選択したテキストはそのまま入り、Mod側で解釈や要約はしません。

```text
[Terminal Context]
Working directory: /home/user/project

Selected output:
----------------
Expected: 200
Received: 500
----------------
```

渡してもターンは始まらないので、「エラーログを選択して渡す → 自分の言葉で指示を書く」という流れで使えます。Claudeの作業中に渡した場合は、同じターンの次のリクエストで読んでくれました。

## 仕組み

構成はざっくり以下のとおりです。

```text
Claude Code プロセス
└─ hooks モジュール (register.tsx)
   ├─ $.process.run ──起動──▶ sidecar（daemon化）
   ├─ $.http.fetch ◀─HTTP over Unix socket─▶ sidecar
   ├─ ui.render ── 画面を Text 行で描く
   ├─ Client (keys.tsx) ── onKey でキーを受ける
   └─ $.session.append ── 選択したテキストを Claude に渡す

sidecar (Bun): PTY + シェル + VTエミュレーション (@xterm/headless)
```

### なぜsidecarが必要か

最初は、Modの `$.process.spawn` でシェルを直接起動すれば済むと思っていました。ところが、`spawn` はstdinが起動時の1回きりで、PTYもresizeもありません。さらに、子プロセスはModのホットリロードでkillされます。

そこで、PTYとVTエミュレーションを別プロセス（sidecar）に持たせることにしました。hooksモジュールは画面の状態を一切持たず、sidecarに問い合わせて描くだけです。こうしておくと、ペインを閉じてもModがリロードされてもシェルが残ります。

### sidecarの中身

| 役割 | 使ったもの |
|------|------|
| PTY | Bun組み込みのPTY対応（`Bun.spawn` の `terminal` オプション） |
| VTエミュレーション | `@xterm/headless`（xterm.jsの画面なし版） |
| HTTPサーバ | `Bun.serve({ unix: path })` |
| 配布 | `bun build --compile` の単一バイナリをModに同梱 |

PTYがBun組み込みなので、`node-pty` のようなネイティブアドオンのビルドが要りません。単一バイナリにしているので、利用する側にBunやNode.jsを入れてもらう必要もありません。hooksモジュールと同じTypeScriptなので、通信プロトコルの型を1か所に書けるのも楽でした。

### 画面の更新はlong-poll

`$.http.fetch` はボディを読み切ってから解決するので、ストリーミングができません。そのため、画面は `GET /frame?since=<ver>&wait=<ms>` のlong-pollで取得しています。

「前のフレームを描き終えてから次を取りに行く」形になるので、そのままbackpressureになります。`seq 1 300000` のような大量出力でもUIは固まりませんでした。

## インストール

### 必要環境

- Linux x64（macOS、Windows、Linux arm64では動きません）
- Claude Code v2.1.287 以降（Modsが必要）
- フルスクリーン表示（マウスで選択したテキストを渡すのに必要）

### 手順

Claude Codeのセッションで以下を実行します。

```text
/plugin marketplace add Coxless/cc-terminal-mod
/plugin install terminal@coxless
```

更新するときは↓

```text
/plugin marketplace update coxless
```

## 使い方

1. `/term` でペインを開く
2. ペインの下の行の `[ Terminal input ]` をクリックする
3. 普通にシェルを操作する
4. Claudeのプロンプトへ戻るときは Escape を押す

### キーバインド

`[ Terminal input ]` がキーを受けている間に使えるキーです。

| キー | 動作 |
|------|------|
| `ctrl+]` | Escape を送る |
| `alt+c` / `alt+d` / `alt+z` / `alt+x` | Ctrl+C / Ctrl+D / Ctrl+Z / Ctrl+X を送る |
| `shift+PageUp` / `shift+PageDown` | 履歴をさかのぼる |
| `alt+v` | 選択モードに入る |
| `alt+a` | マウスで選択したテキストをClaudeに渡す |
| `alt+h` | ヘルプ |

選択モードでは、`h` `j` `k` `l` か矢印で動き、`v` / `V` で始点を置き、`enter` でClaudeに渡します。取り消しは `q` です。

## 制約

公式のMods APIだけで作っているため、いまのところ以下ができません。

- **Escape、Ctrl+C、Ctrl+D、Ctrl+Z、Ctrl+X はそのままではTerminalに届かない。** Claude Code本体が先に処理するためで、上の代替キーを使います
- **ペーストがTerminalに届かない。** Claudeのプロンプト欄に入ってしまいます
- **キーボードだけではTerminalに切り替えられない。** `[ Terminal input ]` のクリックが必要です
- **Terminalの16色は、端末の配色どおりにならない。** 色の指定がClaude Code側のRGBに置き換わるためです

:::message
vimの癖でEscapeを連打すると、フォーカスがプロンプトに戻った状態でClaudeのターンを中断してしまうことがあります。Terminal内のEscapeは `ctrl+]` です。
:::

## 作ってみて分かったこと

Mods APIを触ってみてハマったところを、いくつかメモしておきます。同じようにModを作る方の参考になれば。

### ソケット名にsession idを使ってはいけない

sidecarとの接続先を決めるのに、最初はsession idを使おうとしました。ところが `/clear` でsession idが変わり、その後 `session.start` も来ないため、シェルを見失います。

Claude Code本体のPIDはプロセスの寿命のあいだ変わらないので、こちらをソケット名にしました。あわせて、`session.end` は `/clear` でも来るので、`reason` が `clear` のときはsidecarを止めないようにしています。

### `$` は変数に保存できない

`$` を変数に保存したり関数に渡したりすると、`claude plugin validate` に拒否されます。dispatchをまたぐ処理は、`session.start` の `$` を閉じ込めたクロージャの束を持っておいて呼ぶ形にしました。

簡単な例↓

```typescript
on('session.start', async ($, e, next) => {
  ops = {
    fetch: (url, init) => $.http.fetch(url, init),
    after: (ms, fn) => $.clock.after(ms, fn),
    append: payload => $.session.append({ message: { type: 'user', content: [{ type: 'text', text: payload }] } }),
  }
  return next(e)
})
```

### `ui.render` の中で始めた `$` 呼び出しは中断される

`ui.render` のdispatch内から始めた `$` 呼び出しは、次の再描画で `ui.render: superseded` として中断されます。resizeなどの副作用は `$.clock.after(0, …)` でdispatchの外に出す必要がありました。

### 全角を出すなら `Text` 行で描く

描画は3方式を試しました。

| 方式 | 全角文字 | 選択 |
|------|------|------|
| `Raster` + `$.ui.blit` | 置けない | 取れるが全角は欠ける |
| hooksが描く `Text` 行 | 正しく出る | 正しく取れる |
| `Client` が描く `Text` 行 | 正しく出る | 取れない |

日本語を扱いたいので、hooksモジュールが `Text` 行で描く方式にしました。一方で、生のキーを受け取れるのは `Client` だけです。そのため「画面をクリックしてそのまま入力」と「ドラッグで選択」を同じ領域で両立できず、入力用の `[ Terminal input ]` を別に置く形になっています。

### 受け渡しは `$.session.append`

Claudeへの受け渡しは `$.prompt.submit` も試しましたが、呼んだ瞬間に新しいターンが始まってしまいます。「選択して渡しておき、あとで自分の言葉で指示する」という使い方には `$.session.append` が合っていました。

Claude Codeを使っている最中の「ちょっとターミナルで確認したい」を解消するために、Terminal Modを作りました。公式のMods APIだけでどこまでできるかを確かめる意味もあったのですが、キー入力まわりの制約はあるものの、対話型のシェルが普通に動くところまでは持っていけました。
